# Monitor Config

Компактная панель для внешних мониторов на Windows: яркость, контраст и громкость по **DDC/CI**, плюс автоматика — расписание яркости, глобальные горячие клавиши и запуск вместе с Windows.

Один `MonitorConfig.exe` на .NET 7 (WinForms + WebView2), живёт в трее.

## Запуск

Нужны [.NET 7 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/7.0) (x64) и WebView2 Runtime — в Windows 10/11 он обычно уже установлен.

Сборка (нужен .NET 7 SDK):

```
git clone https://github.com/vladkolchik/monitorconfig
cd monitorconfig
build.cmd
```

Получится `dist\MonitorConfig.exe` — один файл, его можно положить куда угодно.

Повторный запуск при уже работающем приложении просто показывает его окно.

## Управление

| Что | Как |
| --- | --- |
| Яркость | ползунок, колесо мыши (±2), стрелки (±5) |
| Пресеты | кнопки или клавиши `1`–`4`: 10 / 35 / 65 / 100 |
| Контраст, громкость | показываются, если монитор их поддерживает |
| Несколько мониторов | вкладки сверху |

### Автоматика (кнопка с ползунками справа вверху)

- **Запуск с Windows** — прописывает exe в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с ключом `--background`: приложение стартует в трее, без окна.
- **Горячие клавиши** — `Ctrl+Alt+PgUp` / `Ctrl+Alt+PgDn` меняют яркость всех мониторов на ±10 из любой программы. Внизу экрана на секунду всплывает плашка с уровнем — она не забирает фокус и пропускает клики.

  <img src="docs/osd.png" width="300" alt="Плашка яркости">
- **Расписание** — в заданное время яркость всех мониторов выставляется сама. При включении сразу применяется уровень, действующий сейчас.

Пока включены расписание или горячие клавиши, после закрытия окна приложение остаётся в трее: клик по значку открывает окно, в меню — пресеты яркости и «Завершить». Остановить можно и кнопкой «Завершить» на экране автоматики. Без автоматики закрытие окна завершает приложение.

Настройки: `%APPDATA%\MonitorConfig\settings.json`.

## Если монитор «не отвечает»

- Включите **DDC/CI** в экранном меню монитора (часто выключено по умолчанию).
- Встроенные экраны ноутбуков через DDC/CI не управляются.
- Некоторые док-станции и переходники USB-C → HDMI не пропускают DDC/CI.

## Как устроено

```
src/MonitorConfig/
  wwwroot/        интерфейс (HTML/CSS/JS без сборки), вшит в exe как ресурсы
  MainForm.cs     окно с WebView2; запросы к https://monitorconfig.local/api/* обрабатываются в процессе, без сети
  Api.cs          JSON API для интерфейса
  Controller.cs   состояние мониторов, горячие клавиши, расписание, автозапуск
  Ddc.cs          DDC/CI через dxva2.dll на отдельном потоке
  Osd.cs          плашка яркости
  Program.cs      единственный экземпляр, иконка в трее
tests/MonitorConfig.Smoke/   сквозной тест на реальном мониторе
```

Запросы к монитору идут строго по одному, а быстрые движения ползунка схлопываются до последнего значения — шина DDC/CI медленная, так она не захлёбывается.

## Тесты

```
dotnet build MonitorConfig.sln
dotnet run --project tests/MonitorConfig.Smoke            # API, запись в монитор, горячие клавиши и плашка, расписание, автозапуск, запуск exe
dotnet run --project tests/MonitorConfig.Smoke -- --full  # плюс ждёт до ~70 с, пока слот расписания сработает сам
```

Тест работает с реальным монитором, во временной папке настроек и под отдельным именем в ключе Run. Он нажимает горячие клавиши и в конце возвращает исходную яркость. Перед запуском закройте работающий MonitorConfig.
